# Аудит ЛЕКАЛО 1.4.0

Дата проверки: 13 сентября 2026 года.

Область проверки — безопасность работы с мерками и экспериментальными основами, совместимость версий локальных данных, SVG/PDF/DXF/ZIP, адаптивность общего интерфейса, offline PWA, portable Windows-программа и фактически опубликованные GitHub Pages/Release.

## Итог

Версия 1.4.0 прошла локальные, CI, браузерные, offline, Windows-package и live-проверки без известных программных блокеров. Web/PWA и Windows используют один frontend; скачанный из GitHub Release пакет содержит точную копию 90 runtime-файлов тега `v1.4.0`.

Это техническая готовность приложения, а не обещание идеальной посадки. Низ белья остаётся основой для пробного образца со средним риском, мягкий бралетт и топ — экспериментальными основами с высоким риском. Для производства всё ещё обязательны физический макет, примерка и проверка DXF в CAD конкретного цеха.

Первая tag-задача успешно собрала пакет, но Windows PowerShell остановил шаг при проверке отсутствующего Release через stderr команды `gh release view`. Ошибка не затронула код или собранный EXE. В pull request #21 проверка существования Release заменена на GitHub REST-запрос с явной обработкой 404; `--clobber` запрещён, поэтому уже опубликованные файлы нельзя молча заменить.

Тег `v1.4.0` остаётся неизменным и указывает на проверенный application commit `f7dc5d0abd8ed828f52eea0832655612c03c9ed9`. Процессное исправление находится следующим commit в `main` и не меняет frontend или бинарную версию 1.4.0.

## Честные границы

- Правильный повторный ввод мерок уменьшает риск, но не доказывает посадку на теле.
- Низ белья можно передавать только в пробный макет; бралетт и топ явно помечены как экспериментальные.
- Каркасный бюстгальтер не добавлен: для него нужны проверенные основы чашки/стана, семейство каркасов, протокол корня груди и серия физических примерок.
- Размерный ряд — независимое построение по правилам мерок, а не промышленная поточечная градация.
- DXF структурно проверен приложением, но не сертифицирован как AAMA/ASTM и не проверен во всех производственных САПР.
- Импортированный SVG остаётся статическим личным непроверенным лекалом и не становится параметрическим автоматически.
- Данные Windows и Web/PWA хранятся раздельно; перенос выполняется экспортом и импортом JSON/SVG.
- Portable EXE не имеет платной цифровой подписи, поэтому скачанный файл может вызвать SmartScreen.

Правило следующих релизов: пользовательская функция считается готовой только после общего frontend, RU/EN, справки, offline-кэша, Windows-сборки, Web/PWA и телефонно-планшетной проверки. Android/RuStore добавится в эту матрицу после появления реальной оболочки и сборочного проекта.
