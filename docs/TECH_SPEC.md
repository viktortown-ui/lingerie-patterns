# Техническая спецификация

## Назначение и границы

ЛЕКАЛО — статическое offline-first приложение без backend и обязательного frontend-сборщика. Проверяемая область ветки 1.4 — эластичный низ белья, личные шаблоны фасона без мерок и безопасный просмотр статических SVG-заготовок. Мягкий бралетт без каркасов использует четыре реально влияющие мерки, эластичный топ — восемь; обе верхние основы остаются экспериментальными и имеют высокий риск посадки. Каркасные бюстгальтеры не включены: для них нужны типоразмеры каркасов, объёмные чашки и отдельная физическая лаборатория посадки.

## Запуск

В Windows пользователь запускает `LEKALO.exe` либо ярлык `ЛЕКАЛО.lnk` с собственной иконкой. Нативный WinForms-host отображает тот же frontend во встроенном Evergreen WebView2 через локальное virtual-host mapping `https://lekalo-app.example`; HTTP-сервер, окно CMD, PowerShell, отдельная вкладка браузера, Node.js и Python во время работы не запускаются. Один mutex не допускает дублирующих экземпляров, профиль хранится в `%LOCALAPPDATA%\Lekalo\WebView2`, удалённые ресурсы и опасные разрешения запрещены. Старые CMD/VBS/PowerShell-файлы сохранены только как запасной браузерный режим и диагностика и не являются основной desktop-версией.

Веб-версия публикует те же `index.html`, `assets`, `src`, manifest и Service Worker на GitHub Pages или любом обычном статическом HTTPS-хостинге. Она устанавливается как PWA на телефон, планшет и компьютер и после первого успешного открытия работает офлайн. Прямой `file://` не поддерживается, потому что приложение использует нативные ES-модули.

Windows-сборщик копирует весь общий frontend без отдельной ветки интерфейса и сверяет количество и SHA-256 каждого файла. Автотест строит граф импортов от `assets/js/main.js` и требует, чтобы каждый достижимый модуль входил в offline-кэш. Поэтому пользовательская функция считается завершённой только вместе с её адаптивным UI, RU/EN-текстом, справкой, тестами и проверкой обоих каналов поставки.

## Архитектура

```text
index.html
└─ assets/js/main.js        запуск, реестр, простой маршрут
   ├─ src/ui                Home, Editor, Help Center, wizard, preview, state
   ├─ src/patterns          независимые модули изделий
   └─ src/core
      ├─ geometry           Point, Path, Bezier, Offset
      ├─ pattern            контракт модуля и аннотации
      ├─ validate           полевые ограничения и повторная проверка мерок
      ├─ grading            индивидуальные и правиловые пакетные пересчёты
      ├─ templates          строгие шаблоны фасона без мерок
      ├─ import             безопасная нормализация статического SVG
      └─ export             SVG, PDF, ASCII DXF, проверяемый ZIP и статус безопасности
```

Никакие сетевые API не участвуют в построении. UI формируется DOM-методами, фреймворков и runtime-зависимостей нет.

Встроенная справка хранится как одна структурированная двуязычная база разделов и открывается из каждого пользовательского экрана. Она входит в offline-кэш и Windows-пакет; отдельной устаревающей копии справки для мобильных или desktop нет.

Интерфейс использует четыре адаптивных слоя: компактный телефон до 720 CSS px, двухпанельный планшет 721–1000 px, двухпанельный ноутбук/широкий планшет 1001–1400 px и трёхпанельный desktop. На телефоне разделы доступны из нижней панели, панель чертежа прокручивается горизонтально независимо, а сенсорные цели имеют размер не меньше 44 CSS px. Safe-area, динамическая высота `dvh`, низкая landscape-ориентация и split-screen обрабатываются CSS без ответвления геометрического движка.

Редактор держит ограниченную историю из 60 снимков текущих мерок, опций и безопасных поправок. Undo/redo не меняет формулы: оно возвращает входные данные и запускает обычную валидацию и полное повторное построение.

## Данные и версии

В `localStorage` под ключом `lingerie-pattern-state` сохраняются язык, тема, текущий модуль, `draftsByModule`, формат бумаги, профили и `lastProfileIdByModule`. Каждый модуль получает собственный несохранённый черновик и последний выбранный профиль. Профиль содержит устойчивый id, `moduleId`, `schemaVersion`, мерки, опции, безопасные поправки, очищенную запись повторного замера и дату. Экспортируемый проект `lekalo-project` версии 3 содержит версию контейнера и модуля, статус модели и ту же локальную запись проверки мерок.

Импорт проекта всегда пересчитывает геометрию текущим кодом. Поддерживаются только версии контейнера 1–3 и текущая `moduleVersion` либо явно перечисленная модулем `compatibleDraftVersions`; для контейнеров 2–3 `moduleVersion` обязательна. Другая явная версия, невалидные мерки и неизвестные значения опций отклоняются. Известные безопасные поправки приводятся к шагу и ограничиваются диапазоном схемы; отсутствующее или нечисловое значение получает default, а неизвестный ключ не применяется. Строковые JSON-представления допустимых числовых/логических опций канонизируются к типам схемы. Импорт резервной копии атомарен: поддерживается только обёртка `lekalo-profiles` версии 1 и старый формат голого массива, а смешанный валидный/невалидный набор не меняет состояние. Внешний JSON считается редактируемым и потому никогда не переносит разрешение на физический экспорт: запись повторного замера сбрасывается у импортированного проекта и профиля. При запрете `localStorage` приложение остаётся работоспособным в сеансе и показывает честный статус без автосохранения.

Шаблоны фасона имеют отдельный контейнер `lekalo-style-template` и хранят только `moduleId`, исходную `moduleVersion`, опции, ограниченные поправки, название, автора, источник и лицензию. Поле мерок запрещено контрактом. Шаблон применяется только к текущей или явно объявленной совместимой версии модуля. Активная библиотека и карантин несовместимых версий хранятся в разных ключах `localStorage`; трёхфазная запись сохраняет резервную копию до подтверждения активной записи, а повреждённая библиотека не перезаписывается частично. Событие `storage` обновляет библиотеку в других вкладках, а неподтверждённая конкурентная замена блокируется.

Статический SVG сначала разбирается ограниченным XML/SVG-парсером без DOM-вставки исходного текста, затем сохраняется как инертная нормализованная геометрия в IndexedDB. При недоступности IndexedDB используется только память текущего сеанса. Статическая запись всегда получает статус `personal-unverified` и не может приобрести мерки, формулы, градацию или производственный флаг через импорт. Успешная постоянная запись или удаление посылает только сигнал обновления через `BroadcastChannel` с `localStorage`-fallback; другая вкладка перечитывает собственную IndexedDB, а не получает геометрию в сообщении.

## Геометрический контракт

- линия строчки (`seam`) является расчётным контуром изделия;
- линия кроя (`cut`) выводится из неё с учётом припуска каждого типа края;
- сгиб получает 0 мм;
- боковые швы переда и спинки строятся общей высоты;
- передний и задний швы ластовицы имеют независимые ширины;
- A1/A2/B1/B2/C1 являются ограниченными параметрами повторного построения низа, а C1 сохраняет общую высоту парных боковых швов;
- каждая верхняя основа показывает только влияющие на неё мерки: четыре у бралетта и восемь у топа; обе сохраняют статус `experimental` и не заявляют проверенную посадку;
- каждая деталь несёт `grainline`, `stretchline`, метки и технологические данные;
- все координаты хранятся в сантиметрах и должны быть конечными числами.

Горизонтальный масштаб эластичного изделия:

```text
scale = 1 / (1 + workingStretchPercent / 100)
```

Это обратное преобразование от размера тела к размеру детали при заданном рабочем растяжении. Продольный масштаб рассчитывается отдельно.

## Экспорт

SVG, PDF, DXF и размерный пакет считаются физическим экспортом. Он доступен только после второго ввода всех мерок с выбранным способом замера; сравнение подтверждает повторяемость чисел, но не правильность техники и не посадку. Изменение первой мерки автоматически делает прежнее совпадение недействительным. Для экспериментальной основы дополнительно требуется одноразовое подтверждение на каждое скачивание; снять предупреждение постоянно нельзя.

SVG получает физические `width`/`height` в миллиметрах, детерминированный `viewBox` и XML-экранирование. В режиме preview из SVG исключаются печатные карточки и калибровка.

PDF поддерживает A4, A3, Letter и A0. Страница 1 резервируется под калибровку и инструкцию. Детали раскладываются на последующие листы по двум осям с повторением геометрии в зоне нахлёста. Служебные заголовки и карта листов рисуются вне области лекал. Перевод миллиметров в PDF points: `pt = mm / 25.4 × 72`.

DXF экспортируется в детерминированный ASCII DXF R12 с явно объявленными единицами и слоями `CUT`, `SEAM`, `NOTCH`, `GRAIN`, `TEXT`. Кубические кривые преобразуются в замкнутые полилинии с настраиваемым допуском (по умолчанию 0,2 мм). Метаданные деталей записываются в зарегистрированное XDATA-приложение `LEKALO`. Экспорт блокируется при неизвестных единицах, незамкнутых контурах и нечисловых координатах, затем повторно читается строгим DXF-парсером.

Экспериментальный статус разрешается fail-safe по модулю и результату построения. Он навсегда остаётся внутри выдачи: SVG получает видимую плашку и metadata, PDF — предупреждение на контрольной и каждой раскройной странице, DXF — комментарии, XDATA и видимый `TEXT`, а имя файла — суффикс `EXPERIMENTAL_TOILE_ONLY`. Если хотя бы один вариант размерного ряда экспериментальный, этот статус наследуют имя ZIP, manifest и подтверждение скачивания.

Это семантически ориентированный обмен для швейных CAD, но не сертифицированный AAMA/ASTM-профиль. Контрольный файл принят, сохранён и снова открыт независимой библиотекой `ezdxf`, что подтверждает читаемость структуры, но не заменяет целевую производственную CAD. До производственного статуса обязателен round-trip через систему выбранного цеха с проверкой масштаба, кривых, надсечек, долевой и метаданных.

Размерный пакет хранит отдельный DXF на каждый именованный вариант и JSON-manifest в детерминированном ZIP32 без сжатия. Проверяются структура ZIP, CRC и повторное чтение каждого DXF. Пакет по полным меркам называется индивидуальным пересчётом; пакет по прибавкам к базовым меркам — правиловым пересчётом. Оба режима намеренно помечены `industrialPointGrade: false`. Повторный замер подтверждает только введённую базу; вычисленные размеры не получают ложную отметку проверки, а manifest хранит `verificationScope: base-profile-only` и `derivedMeasurementsDirectlyVerified: false`.

## Offline

Service Worker предварительно кэширует оболочку и полный статический граф ES-модулей, использует network-first с четырёхсекундным дедлайном для HTML/JS/CSS и cache-first для остальных ресурсов. HTML-оболочка никогда не подставляется вместо отсутствующего JS/CSS. Номер `BUILD` меняется при релизе, старые кэши удаляются при активации. Локальный launcher работает и без Service Worker; кэш нужен для установленной PWA/GitHub Pages.

## Проверки

Команда `node --test` охватывает:

- базовую геометрию и offset;
- контракт всех публичных модулей;
- наборы пропорций и граничные мерки;
- конечность/замкнутость контуров, самопересечения и сопряжение;
- семантику линий SVG, локализацию и XML-безопасность;
- размеры страниц, калибровку, тайлинг и нахлёст PDF;
- единицы, слои, замкнутость и внутренний round-trip DXF;
- детерминированность размерных пакетов и ZIP, CRC и опасные пути;
- миграцию состояния, отказ хранилища, профили/черновики по моделям, безопасное хранение повторных мерок, типы опций и очистку ресурсов preview/download;
- верхние основы на минимальных, исходных и максимальных мерках, точный набор реально влияющих полей и совместимость черновиков `0.2.0 → 0.3.0`;
- блокировку физического экспорта до повторного замера и неустранимую маркировку экспериментальных SVG/PDF/DXF/ZIP;
- строгий контракт шаблонов, отсутствие мерок, совместимость версий и атомарное локальное хранение;
- безопасный SVG-разбор, лимиты сложности, блокировку активного содержимого, калибровку, хэш источника и нормализованный экспорт;
- русскую/английскую локализацию.

Релизный fuzz-аудит отдельно строит допустимые случайные сочетания мерок, опций и A/B/C-поправок для каждого публичного модуля, проверяет конечность, замкнутость и отсутствие самопересечений, затем формирует SVG/DXF и выборочно PDF. Найденные сочетания становятся постоянными регрессионными тестами.

Перед публичной пометкой «проверено посадкой» отдельно нужны реальные распечатки и серия физических макетов.
